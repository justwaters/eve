A second opinion on every pull request.

Eve is a reusable GitHub Actions workflow. Several AI models read each pull request, one more combines what they found, and every serious finding is checked against the code before it reaches you.

View on GitHub

What she posts

One comment on the pull request, and two checks. This is a real review of a one-line change:

🤖 Automated Code Review
🚦 Executive Verdict: No verified blockers.
The PR is stable and ready to merge; it adds only an inert HTML comment to README.md and introduces no functional, security, or performance changes.
Models that failed to respond are listed at the bottom of every review, so a quiet model is never hidden.

How it works

  1. Read the diff

    Eve gets the pull request's diff through the GitHub API. She never checks out the pull request's code.

  2. Ask eight models

    Eight NVIDIA-hosted models review the diff independently, in parallel.

  3. Combine

    A ninth model merges their answers into one list of findings.

  4. Check every claim

    Each blocker and warning is checked against the real file. A finding whose quoted code isn't there is dropped, and one that can't be proved is listed apart, never as a finding.

  5. Rate by who could trigger it

    A confirmed finding is rated by who could hit it and what they already hold, so a bug only an admin can reach is not shouted like an open hole.

What she can do

Review on every push

Opened, updated, reopened or marked ready. A newer push cancels a review that is still running.

Know your project

Put facts the code doesn't show in .github/eve-context.md, and she reads them before she judges.

Take commands

Owners, members and collaborators can comment review, pause, resume or help addressed to her.

Speak as an App

Optionally post under a GitHub App's name and avatar instead of github-actions[bot].

Stay honest

A failed or partial review ends neutral, never as a failure, and the models that didn't answer are named.

Be tested

The checking code has its own tests, run with a fake model, in the repository.

Turn it on in a repository

  1. Copy examples/eve.yml to .github/workflows/eve.yml.
  2. Add the repository secret NVIDIA_API_KEY to that repository. Secrets are per repository.
  3. Pin the uses: line to a commit: the workflow runs with your secrets.
jobs:
  eve:
    uses: justwaters/eve/.github/workflows/review.yml@<commit>
    secrets:
      NVIDIA_API_KEY: ${{ secrets.NVIDIA_API_KEY }}

Set the repository variable AI_REVIEW_ENABLED=false to turn her off again.

What to know first

Your code leaves your control. The diff, title and description of each reviewed pull request are sent to NVIDIA. Don't enable Eve on a repository whose code must stay in-house.
She is advisory, not a security gate. Don't make her checks required: a pull request's own text can try to talk a model into dismissing a finding. A person still decides what merges.
CostFree on public repositories. On private ones she uses your Actions minutes (about 7 minutes per review), plus whatever your NVIDIA key costs.
Big diffsOnly the first 60,000 characters are reviewed.
SpeedA few minutes: the hosted models are shared, and a slow one can take up to 4 minutes before it's marked as failed.
